## 任务

帮我将整个开启本地测试的复杂流程，简化为一个 Python 应用或者脚本（随便你看哪种形式比较合适）。

达成的效果如下：
1. 自动化环境搭建：我输入一个命令之后，它能自动将本地的测试环境搭建好，并输出两个网址，一个是前端，一个是后端。
2. 数据库检查：
   (a) 如果过程中没有检测到 DB 文件，它需要询问并引导我创建超级管理员账号和密码。
   (b) 如果已有 DB 文件，则直接运行并输出本地测试应用即可。
3. 端口占用处理：如果遇到端口被占用的情况，程序需要具备自动处理能力，比如自动换一个可用的端口。

## 修改

1. **修复前端 EIO 崩溃错误**：在 `start_local_test.py` 启动前端 `subprocess.Popen` 时，加入了 `stdin=subprocess.DEVNULL`，防止 Vite 尝试读取无 TTY 的标准输入而异常退出。
2. **代理端口动态化匹配**：测试脚本会将自动分配到的可用后端端口通过环境变量 `VITE_API_URL` 传递给前端进程；同时将 `frontend/vite.config.js` 中的代理目标修改为使用 `process.env.VITE_API_URL`，确保前端发起的代理请求始终能打到正确的动态后端端口。
3. **主进程前台挂起与进程清理**：在 `start_local_test.py` 末尾增加前台死循环进行挂起，并捕获 `KeyboardInterrupt` (Ctrl+C) 信号。当用户中断运行退出时，自动通过 `.terminate()` 和 `.wait()` 终止前后端子进程，避免因未正常清理产生的“僵尸后台服务”不断累积占用更多端口。
4. **绑定 IPv4 并在被占用时阻断重启漂移**：在前端启动命令中增加了 `--host 127.0.0.1` 强行绑定 IPv4（取代 Node 的默认 `localhost` 即 `::1` IPv6 带来的无法访问），同时增加 `--strictPort` 禁止 Vite 在热更新被触发时随机抢占下一个端口导致终端内显示的端口与真实不符。
