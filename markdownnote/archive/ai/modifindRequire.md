## 需求

作业上传系统


学生不必输入自己的姓名，只需要输入学号和密码即可登陆

学生登录之后的页面应当显示他自己的名字以及学号等信息。

比如说：在作业列表的右边显示这些信息。

在教师面板中查看每一次作业提交的时候，你不仅需要学号，还需要显示学生的名字信息。我还需要以下功能：

1. 一键导出学生作业完成情况
   (a) 不仅可以下载最新的 ZIP 文件，还可以一键导出 CSV 表格
   (b) 表格应记录每个学生的学号、姓名以及作业完成状态（如“未交”等）, 假如学生提交了作业而我还没评，系统就默认显示为 85 分
2. 教师端快速评分功能
   (a) 在查看作业详情时，教授可以直接进行评分操作
   (b) 直接默认成 85 分
   (c) 支持手动调整，例如修改为 A-、A+、B+ 或进行分数的上下浮动调整


要能下载单次的所有作业, 需要有一个功能可以下载所有作业为 ZIP 文件

在查看单次作业的提交情况时，我需要提供一个功能：支持单独下载某个学生的某一次作业，而不是必须下载全部的 ZIP 文件。
 

提供 AI 接口，让人调用 AI 给作业评分同时 AI 也可以给作业做总结。

给出一个方案，防止我不小心在更新时覆盖 backend 目录下的 db 文件，导致数据丢失。

因为有可能我同时在本地和云端进行测试，使用的是同一个存储桶。你怎么能够保证我在更新的时候，不会覆盖掉存储桶里已经存储的文件？

你最好在开发环境把文件上传到存储桶时，看看有没有什么办法能够保证：
1. 我们在测试环境之中，我自己测试一些学生的名字、学号时，不会把原本的文件覆盖掉。
2. 同样的，你需要保证在任何情况下都不会覆盖掉学生提交的文件。

1. .pdf
2. .docx
3. .md
4. .txt

6. Python 格式等

请直接提供这些默认选项。如果有什么要添加的话，你再让我添加。或者说，让学生提交编程作业的时候，这些格式够不够？

## Plan

### 一、 核心需求解析与现状比对

1. **学生端体验优化**
   - **现状**: 登录可能要求提供姓名进行校验，页面缺乏个人信息展示。
   - **需求**: 仅需“学号+密码”登录；登录后（如作业列表右侧）全局展示“姓名+学号”。
   - **接口现状补充**: 当前 student router 前缀为 `/api/assignments`，尚无可直接获取当前学生信息的 `/me` 端点，需要明确新增。
2. **教师端管理与评分功能提升**
   - **现状**: 只能查看和统一下载所有作业 ZIP，缺乏快捷批改和数据导出。
   - **需求**: 
     - 列表中需展示学生姓名与学号。
     - **导出 CSV**: 包含学号、姓名、提交状态。对于已交未改的，系统默认打分为 85 分。
     - **快速评分**: 默认带出 85 分，支持微调数字，或直接使用 A+、A-、B+ 等等级评分。
     - **单点下载**: 支持单独下载某位学生的单次作业压缩包/文件；下载参数需明确语义，避免 `student_id` 歧义。
3. **作业格式限制默认配置**
   - **需求**: 创建作业时，默认提供 `.pdf, .docx, .md, .txt, .ipynb, .py` 等选项供教师勾选。
4. **数据与存储安全 (核心痛点)**
   - **防覆写数据库**: 本地更新/重启时，如何防止 `backend` 目录下的 `.db` 文件丢失。
   - **防污染/防覆写 COS (对象存储)**: 本地测试、云端测试共用一个 Bucket 时的隔离方案，且绝不覆盖学生的历史提交。

### 二、 详尽实施计划 (Detailed Action Plan)

#### 阶段 1：基础设施与资产安全加固 (Infrastructure & Security) - *最高优先级*
*目标：保证在后续开发和部署中，数据库和上传的文件绝对安全。*
1. **本地数据库 (SQLite) 保护**:
   - 检查并修改项目根目录和 `backend` 的 `.gitignore`，确保 `*.db` 和 `*.sqlite3` 被忽略，防止被意外提交或 pull 时覆盖。
   - 补充数据库迁移机制，避免“仅改 `models.py` 导致旧库结构不变”：
     - 引入 Alembic 并建立迁移目录。
     - 先执行一次基线迁移（基于当前线上/本地实际库状态）。
     - 后续新增字段通过迁移脚本（`ALTER TABLE`）落库，而不是依赖 ORM 自动建表。
     - 在 README/部署脚本中固定执行顺序：备份数据库 -> `alembic upgrade head` -> 启动服务。
2. **COS 对象存储环境隔离与防覆盖方案**:
   - **环境隔离**: 在配置中引入 `ENV` 变量（如 `DEV` / `PROD`），上传时根据环境变量自动在路径前追加前缀（如 `dev_env/` vs `prod_env/`）。
   - **代码落点修正**: 目前 Key 是在 `student.py` 的 `submit_assignment` 函数里硬编码生成，不在 `cos_utils.py`；应优先修改该函数中的 Key 组装逻辑。
   - **防覆写机制**: `submit_assignment` 中的 Key 生成规则必须包含环境前缀 + assignment_id + 学号 + 时间戳 + UUID（如 `dev/submissions/{assignment_id}/{student_no}/{timestamp}_{uuid}_{filename}`），确保同名文件永不覆盖。

#### 阶段 2：数据库模型更新 (Database Migration)
*目标：在后端的 `models.py` 中增加支持评分和成绩的字段。*
1. **修改 `Submission` 模型**:
   - 增加 `score` (Float): 记录具体分数（统一为 Float，避免类型歧义）。
   - 增加 `grade` (String): 记录等级 (A+, B+ 等)。
   - 增加 `is_graded` (Boolean): 标识是否已经批改。
2. **迁移脚本要求**:
   - 为 `score/grade/is_graded` 生成对应 Alembic migration。
   - 为历史数据设置默认值策略：
     - 已提交未评分记录默认 `score=85.0`、`is_graded=false`（表示默认显示分，不代表教师已确认批改）。
     - `grade` 可为空，允许教师后续录入 A-/A+ 等。

#### 阶段 3：后端接口开发与改造 (Backend APIs)
1. **Auth 接口 (`auth.py`)**: 改造学生登录逻辑，去除 `name` 验证，仅通过 `student_id` 和 `password` 登录。
2. **Student 接口 (`student.py`)**:
   - 在当前 router（prefix=`/api/assignments`）下新增 `GET /me`，完整路径为 `GET /api/assignments/me`。
   - 返回字段至少包含 `student_id`（学号字符串）和 `name`，用于前端右侧用户信息展示。
3. **Admin - 作业管理与下载接口 (`admin.py`)**:
   - 新增 `GET /assignments/{id}/submissions/{student_no}/download` 以供单学生作业下载。
   - 参数语义明确：`student_no` 表示学号字符串（如 `20230001`），不是数据库主键 ID。
   - 新增 `GET /assignments/{id}/export_csv` 接口以导出含有 85 分默认值的 CSV 成绩单。
   - 新增 `PATCH /submissions/{sub_id}/grade` 以接收教师评分。

#### 阶段 4：前端视图与交互改造 (Frontend Vue3)
1. **学生端**:
   - `Login.vue`: 移除姓名输入框。
   - `AssignmentList.vue`: 调用 `GET /api/assignments/me` 并增加区域显示“姓名 + 学号”。
2. **教师端**:
   - `AssignmentManage.vue`: 新增默认格式勾选（.pdf, .docx, .md, .txt, .ipynb, .py, .zip）。
   - `SubmissionDetail.vue`: 增加学生姓名展示、单人下载按钮、CSV 导出按钮、快捷等级/数字评分组件。

#### 阶段 5：联调测试与文档更新
1. 验证 Alembic 迁移在已有 SQLite 上可重复执行（含备份与回滚演练）。
2. 验证 COS 隔离存储与唯一 Key 规则在本地/云端并行测试下不会覆盖历史文件。
3. 验证 `GET /api/assignments/me` 与单学生下载接口参数语义一致（学号字符串）。
4. 更新设计文档与 README。
